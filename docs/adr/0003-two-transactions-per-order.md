# 0003. 주문 하나를 접수·정산 트랜잭션 두 개로 처리

- 상태: 채택
- 날짜: 2026-10-28

## 배경

매칭은 메모리에서 하고 잔고는 DB에 있다. 매칭 결과와 DB가 어긋나면 안 되고, 서버가 중간에 죽어도 복구할 수 있어야 한다.

## 결정

1. 접수 트랜잭션: 포인트·주식을 조건부 UPDATE로 묶고 주문을 `PENDING`으로 저장한다.
2. 메모리 매칭.
3. 정산 트랜잭션: 체결, 상대 주문 잔량, 차액 환불, 주문 상태를 한 번에 반영한다. 계정 행은 id 순서로 갱신한다.

정산이 실패하면 주문을 취소하고 호가창을 DB에서 다시 쌓는다. 그것도 실패하면 그 구단 거래를 멈춘다. 재시작 때 `PENDING` 주문은 취소한다.

## 검토한 대안

- 체결 한 건마다 트랜잭션 하나: 한 주문이 여러 건에 체결되면 중간 상태가 DB에 남는다.
- 트랜잭션 하나로 접수와 정산: 잔고 확인 전에 매칭이 먼저 일어나 메모리 호가창을 되돌리기 어렵다.

## 결과

- 매칭 시점에 돈이 이미 묶여 있어 매칭 중 잔고를 다시 볼 필요가 없다.
- 실패 처리 경로가 둘(정산 실패, 재시작) 생기고 각각 테스트가 있다.
