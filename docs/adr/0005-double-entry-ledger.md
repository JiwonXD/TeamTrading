# 0005. 복식부기 원장과 대사

- 상태: 채택
- 날짜: 2026-10-28

## 배경

잔고 칼럼은 현재 값만 보여주고 어떻게 그 값이 됐는지는 남기지 않는다. 코드 실수나 DB 직접 수정으로 잔고가 틀어져도 알 수 없다.

## 결정

포인트·주식이 움직일 때마다 잔고 갱신과 같은 트랜잭션에서 전표를 남긴다. 전표는 자산별 분개 합이 0이어야 만들어지고, 처음 생기는 몫은 발행처(`SYSTEM`) 칸에서 나온다. 대사는 원장을 계정·자산·칸별로 합산해 잔고와 비교하고, 합이 0이 아닌 전표를 찾는다. 두 쪽은 한 읽기 트랜잭션에서 읽는다.

## 검토한 대안

- 잔고를 원장 합계로만 계산: 조회마다 합산이 필요하고, 비교할 독립 기록이 없어진다.
- 변경 이력(감사 로그)만 남기기: 합이 맞는지 검증할 구조가 없다.

## 결과

- 잔고와 원장이 서로를 검증한다. 대사 API가 불일치 칸을 바로 보여준다.
- 쓰기 양이 늘어난다 (체결 한 건당 분개 최대 5행).
- 원장이 계속 커지므로 일 마감 때 잔고 스냅숏을 남기고 그 이후분만 합산하는 방식이 필요해진다 (M1).
