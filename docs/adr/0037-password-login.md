# 0037. 아이디·비밀번호 가입을 더하고, 비밀번호는 bcrypt·실패 5번 잠금·메일 재설정으로 지킨다

- 상태: 채택
- 날짜: 2026-11-08

## 배경

로그인은 카카오·Google 소셜 로그인만 있었다(개인정보는 제공자 회원 번호만 받는다). 소셜 계정을 연결하기 꺼리는 사람도 바로 쓸 수 있게 아이디·비밀번호 가입을 더하기로 했다. 비밀번호를 직접 받으면 저장·유출·무차별 대입·분실을 서비스가 책임져야 하므로, 받는 정보를 최소로 하고 막아야 할 것을 정했다.

## 결정

- **받는 정보:** 아이디(영문 소문자·숫자 4~20자, 숫자로 시작해도 됨, 대소문자 구분 없음), 비밀번호, 이메일(선택). 닉네임은 소셜 가입과 같이 "투자자+숫자"로 시작하고 기존 규칙대로 바꾼다. 아이디는 화면에 보이지 않는다.
- **비밀번호 규칙:** 8~64자, 영문과 숫자를 모두 넣고, 한글·공백은 쓸 수 없으며(bcrypt의 72바이트 한도 안), 아이디를 그대로 넣을 수 없다.
- **저장:** bcrypt 해시(`password_logins.password_hash`)만 저장한다. 계정 연결은 소셜과 같이 `account_identities`에 `('password', 아이디)`로도 남겨, 가입 보상 한 번·탈퇴 후 30일 재가입 제한·탈퇴 시 연결 삭제를 똑같이 받는다.
- **무차별 대입 방어:** 같은 아이디로 연속 5번 틀리면 15분 동안 맞는 비밀번호도 받지 않는다. 비밀번호를 맞춰 보기 **전에** 조건부 UPDATE 한 문장으로 시도를 세고 잠근다. 그래서 같은 아이디로 동시에 요청을 쏟아부어도 잠기기 전까지 5번만 맞춰 본다. 맞으면 횟수를 0으로 되돌린다.
- **아이디 존재 숨기기:** 없는 아이디와 틀린 비밀번호는 같은 문구("아이디 또는 비밀번호가 맞지 않아요")로 답하고, 없는 아이디도 bcrypt 비교를 한 번 해서 응답 시간 차이를 줄인다(가입 화면의 아이디 확인은 겹침을 알려 줄 수밖에 없다).
- **비밀번호 재설정:** 가입 때 이메일을 넣은 계정만 된다. 아이디와 이메일이 맞으면 32바이트 무작위 토큰을 담은 링크(`/#reset-토큰`)를 메일로 보내고, DB에는 토큰의 SHA-256만 둔다. 30분 안에 한 번만 쓸 수 있고(조건부 UPDATE), 새로 받으면 이전 링크는 못 쓴다. 같은 아이디로는 1분에 한 번만 보낸다. 맞든 틀리든 같은 답을 한다. 링크 주소는 요청의 Host 헤더가 아니라 설정값(`SITE_URL`)으로 만든다.
- **메일 발송:** SMTP(`MAIL_HOST` 등). 설정이 없으면 재설정을 끄고 화면에서 "비밀번호 찾기"를 숨긴다. `spring.mail.*` 대신 별도 설정을 쓴다. 빈 값이어도 Spring Boot가 발송기를 만들어 버리기 때문이다.
- **소셜 연동:** 아이디로 가입한 계정은 내 투자 화면 "로그인 수단"에서 구글·카카오를 같은 계정에 더 붙일 수 있다(계정 하나에 로그인 수단 여럿, `account_identities`가 원래 1:N이다). 연동 버튼을 누르면 세션에 "이 계정에 붙일 것"(계정 id·제공자·시각)을 적고 제공자 로그인으로 보낸다. 돌아왔을 때 그 표시가 10분 안의 것이면 새 계정을 만들지 않고 지금 계정에 연결하고, 로그인 상태를 원래 계정으로 되돌린다. 다른 계정에 이미 연결된 소셜 계정, 같은 제공자의 두 번째 계정은 붙이지 않는다. 가입 보상은 다시 주지 않는다. 연동 해제는 아직 없다.
- **탈퇴:** 아이디·비밀번호 해시·이메일·재설정 토큰을 바로 지우고, 아이디의 해시만 30일 남겨 같은 아이디 재가입을 막는다.

## 이유

- 비밀번호를 해시로만 두면 DB가 새도 원문은 나가지 않는다. bcrypt는 느리게 설계돼 유출된 해시를 대입해 보기도 어렵다.
- "틀릴 때 센다"는 방식은 맞춰 보는 동안 다른 요청이 같은 횟수를 읽어 한도를 넘는다. 먼저 세면 한도가 정확히 지켜진다.
- 이메일을 필수로 받으면 개인정보가 늘고 가입이 번거로워진다. 선택으로 두고, 넣지 않은 사람은 비밀번호를 잊으면 찾을 수 없다는 점을 가입 화면 도움말에 둔다.

## 검토한 대안

- **IP별 잠금:** 집·학교처럼 IP를 나눠 쓰는 사람이 함께 막히고, Cloudflare 뒤라 원래 IP를 따로 믿어야 한다. 아이디별 잠금으로 시작한다. 잠금을 악용해 남의 아이디를 15분 막을 수는 있으나 계정을 뺏기지는 않는다.
- **이메일을 아이디로:** 아이디만으로 개인정보가 되고, 화면 어디서든 실수로 노출되면 곤란하다.
- **잠금 대신 캡차:** 외부 서비스가 필요하다. 나중에 필요해지면 더한다.
