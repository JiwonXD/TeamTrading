# 0001. 저장소는 MySQL(InnoDB)

- 상태: 채택
- 날짜: 2026-10-28

## 배경

잔고·주문·체결을 서버 재시작 후에도 잃지 않아야 하고, 동시에 들어오는 주문에서 잔고가 음수가 되거나 갱신이 유실되면 안 된다.

## 결정

MySQL 8.4(InnoDB)를 쓴다. 스키마는 Flyway로 관리하고, 테스트는 H2 MySQL 모드로 빠르게 돌리며 동시성 검증은 실제 MySQL에서 한다.

## 검토한 대안

- PostgreSQL: 기능은 충분하다. 장단점을 비교한 뒤 운영 자료와 사용 사례가 많은 MySQL을 골랐다.
- 메모리 + 파일 저널만: 단순하지만 조회·대사·운영 도구를 모두 직접 만들어야 한다.

## 결과

- 행 잠금과 조건부 UPDATE, CHECK 제약으로 잔고 음수를 막는다.
- 여러 계정 행을 갱신할 때 교착을 피하려면 갱신 순서를 정해야 한다 (0003).
- H2와 MySQL의 차이로 테스트가 실제 동작을 다 보여주지 못하므로 CI에서 MySQL 동시성 테스트를 따로 돌린다.
