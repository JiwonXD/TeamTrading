# 0036. 매일 00:00~00:30(한국 시간)은 점검시간으로 매매를 막는다

- 상태: 채택
- 날짜: 2026-11-08

## 배경

자정에는 일 마감(기준가 교체, 가격제한폭 밖 대기 주문 취소)과 배포·백업 같은 운영 작업이 몰린다. 이때 주문이 섞이면 사용자는 바뀌기 직전 기준가로 낸 주문이 곧바로 취소되는 일을 겪고, 운영자는 작업 중 체결을 신경 써야 한다. 실제 거래소처럼 매일 정해진 시간에 매매를 쉬기로 했다.

## 결정

- **시간:** 매일 00:00 이상 00:30 미만, 한국 시간(`Asia/Seoul`). 서버 컨테이너나 이용자 기기의 시간대와 상관없이 한국 시간으로 계산한다(`MarketHours`).
- **서버가 1차로 막는다.** 점검시간에는 매수·매도 주문을 `422`와 안내 문구로 거절한다. 동시호가·VI 단일가 매매도 이 시간에는 체결하지 않고 00:30 이후 첫 차례에 체결한다.
- **막지 않는 것:** 주문 취소(묶인 포인트·주식을 돌려받는 일), 조회, 공모 청약, 배당 지급.
- **멱등성 유지:** 점검시간 직전에 접수된 주문을 같은 주문 번호로 다시 보내면 거절하지 않고 처음 접수 결과를 돌려준다. 응답을 못 받은 클라이언트가 "실패"로 오해하지 않게 하기 위해서다.
- **화면은 안내용이다.** 시작할 때 `GET /api/market-hours`로 점검시간을 받아(`{ maintenance: { start, end, timeZone } }`, 꺼져 있으면 `null`) 그 시간에 구매·판매 버튼을 막고 안내 문구를 보여 준다. 5초마다 다시 확인해 새로고침 없이 바뀐다.
- **설정:** `fanchart.trading.maintenance`(기본 `true`). 시연(`demo`) 프로필과 테스트는 끈다. CI의 E2E·장애 복구·배포 점검이 한국 자정 무렵(UTC 15:00)에 돌아도 실패하지 않게 하기 위해서다.

## 이유

- 화면만 막으면 오래 열어 둔 탭, 시계가 틀린 기기, 직접 API를 부르는 요청은 막지 못한다. 거절은 서버가 하고 화면은 같은 시간을 서버에서 받아 보여 주기만 한다.
- 시간을 화면 상수로 따로 두면 서버와 어긋날 수 있어 서버가 내려 준다.

## 검토한 대안

- **점검시간에 대기 주문 전부 취소:** 사용자 주문을 운영 사정으로 지우게 되고 요청에도 없었다. 대기 주문은 그대로 두고 새 주문과 체결만 막는다.
- **시세 데이터(Quote)에 점검 여부를 넣기:** 3초 갱신에 기대야 하고 자정에 바뀐 사실을 알리려면 별도 발행이 필요하다. 시간만 내려 주고 화면이 계산하는 편이 단순하다.
