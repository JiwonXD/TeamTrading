# 0015. 정합성을 지표로 내보내고 대사가 어긋나면 경보한다

- 상태: 채택
- 날짜: 2026-11-02

## 배경

대사(0005)는 운영자가 API를 불러야만 돌았다. 잔고가 원장과 어긋나도 누가 보기 전까지 아무도 모른다. 체결 처리량, 거래 정지, 실시간 시세 끊김도 로그를 뒤져야 알 수 있었다.

## 결정

- Spring Boot Actuator와 Micrometer Prometheus 레지스트리를 쓴다.
- 지표는 관리 포트(8081)에서만 연다. 서비스 포트로는 내부 상태가 새어 나가지 않는다. health와 prometheus 말고는 열지 않는다.
- 대사를 5분마다 돌리고 결과를 `teamtrading_reconciliation_balanced`(1/0) 게이지로 낸다. 대사 자체가 예외로 실패해도 0으로 둔다. "확인하지 못함"을 "맞음"으로 보지 않기 위해서다.
- 체결 지표는 체결 업데이트 이벤트에서 센다. 매칭 경로에는 카운터 증가만 더한다.
- 구단 태그는 10개 남짓이라 카디널리티 걱정이 없다. 계정 id는 태그로 쓰지 않는다.

## 결과

- 원장 불일치, 거래 정지, 주문 지연이 경보 규칙 하나씩으로 잡힌다(docs/operations.md).
- 대사는 전체 원장을 읽는다. 원장이 커지면 주기를 늘리거나 일 마감 스냅숏 이후분만 보는 증분 대사로 바꾼다.
- 테스트 컨텍스트는 메트릭 내보내기를 끄므로, 테스트는 레지스트리 값과 관리 포트 health로 확인한다.
