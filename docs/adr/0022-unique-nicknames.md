# 0022. 닉네임은 한 계정만 쓰고, DB 고유 인덱스로 지킨다

- 상태: 채택
- 날짜: 2026-11-02

## 배경

가입하면 `투자자` + 4자리 번호를 닉네임으로 붙였고, 바꿀 방법이 없었다. 번호가 9,000개뿐이라 가입자가 100명만 넘어도 같은 닉네임이 생길 확률이 높았다. 리더보드, 토론방, 이상거래 감시 화면은 계정 id 대신 닉네임만 보여주므로, 같은 닉네임이 둘이면 누가 누구인지 구분할 수 없다. 화면도 리더보드 행을 닉네임으로 구분하고 있었다.

## 결정

- **한 닉네임은 한 계정만 쓴다.** `accounts.nickname`에 고유 인덱스를 둔다. MySQL 기본 정렬 규칙이라 대소문자만 다른 닉네임(`Alice`, `alice`)도 같은 닉네임으로 본다.
- **기존 중복은 마이그레이션에서 정리한다.** 먼저 가입한 계정이 그대로 쓰고, 나머지 계정은 뒤에 `_` + 계정 id 앞 6자리를 붙인다(20자 안).
- **기본 닉네임은 `투자자` + 6자리.** 이미 쓰이는 번호면 다시 뽑는다(10번까지). 겹친 INSERT는 그 문장만 실패하고 가입 트랜잭션은 이어 쓴다. 이 동작은 CI의 MySQL 작업에서 확인한다.
- **변경 규칙.** 한글(완성형)·영문·숫자·밑줄 2~12자. `운영`, `관리자`, `admin`, `팀트`, `teamtrading`이 들어간 닉네임은 운영자 사칭이 될 수 있어 막는다. 한 번 바꾸면 7일 동안 다시 바꿀 수 없다(리더보드에서 이름을 자주 바꿔 헷갈리게 하지 못하게). 실패한 시도는 7일을 쓰지 않는다.
- **검사는 한 문장으로 한다.** 변경 주기는 조건부 UPDATE(`nickname_changed_at`이 7일 전 이전이거나 없을 때만)로, 겹침은 고유 인덱스로 검사한다. 두 사람이 같은 닉네임을 동시에 골라도 한 사람만 갖고, 한 계정이 동시에 두 번 바꿔도 한 번만 바뀐다.
- **바꾸면 지난 글에도 새 닉네임이 보인다.** 글과 탐지 기록은 계정 id만 저장하고 닉네임은 볼 때 붙인다.

## 검토한 대안

- **바꾼 닉네임만 따로 고유하게 관리:** 기본 닉네임이나 시연 계정 이름과 겹칠 수 있어 사칭을 막지 못한다.
- **닉네임 옆에 계정 번호 태그(`이름#1234`)를 붙여 중복 허용:** 화면마다 태그를 보여줘야 하고, 사용자가 태그를 보지 않으면 사칭을 막지 못한다.
- **먼저 조회해서 겹치는지 보고 바꾸기:** 조회와 변경 사이에 다른 사람이 같은 닉네임을 가져갈 수 있다.

## 결과

- 이미 겹친 닉네임을 쓰던 계정은 마이그레이션 뒤 닉네임에 번호가 붙는다. 베타 전이라 실제 사용자는 없다.
- H2(테스트)는 대소문자를 구분해 비교한다. 대소문자 겹침 검사는 MySQL에서만 확인된다.
