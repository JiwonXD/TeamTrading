# 0004. 클라이언트 주문 번호로 멱등 처리

- 상태: 채택
- 날짜: 2026-10-28

## 배경

네트워크가 끊겨 응답을 못 받은 클라이언트가 주문을 다시 보내면 같은 주문이 두 번 체결될 수 있다.

## 결정

클라이언트가 주문마다 `clientOrderId`를 만들어 보낸다. `UNIQUE (account_id, client_order_id)`로 한 번만 저장하고, 같은 번호의 재요청에는 저장된 결과를 그대로 돌려준다. 같은 번호로 내용이 다른 주문이 오면 409로 거절한다. 접수 전에 거절된 주문은 저장하지 않아 같은 번호로 다시 보낼 수 있다.

## 검토한 대안

- 서버가 요청 해시로 중복 판단: 같은 내용의 의도된 두 주문을 구별하지 못한다.
- 짧은 시간 동안만 기억하는 캐시: 재시작하면 잊는다.

## 결과

- Stripe 멱등키, FIX ClOrdID와 같은 방식이라 설명하기 쉽다.
- 클라이언트가 번호를 재사용하지 않도록 UUID를 쓰게 안내해야 한다.
