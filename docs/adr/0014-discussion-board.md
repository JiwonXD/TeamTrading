# 0014. 종목토론방 글은 서버에 저장하고, 게시글 보상은 숨김 없이 남은 글에 늦게 준다

- 상태: 채택
- 날짜: 2026-11-02

## 배경

글을 쓰면 포인트(2,000P, 하루 3번)를 준다. 보상이 걸리면 짧은 글 도배, 같은 글 반복, 광고 링크가 생긴다. 글을 쓰자마자 주면, 쓰고 바로 지우거나 신고로 숨겨질 글로도 포인트를 모을 수 있다.

## 결정

- **저장.** `posts`에 구단, 작성자, 본문, 글을 쓸 때 보유 여부(보유 배지), 상태(VISIBLE, HIDDEN, DELETED), 신고 수, 보상 상태를 둔다. 응답에는 닉네임만 넣고 계정 id는 내보내지 않는다.
- **쓰기 제한.** 계정 행을 잠그고 확인하므로 동시에 보내도 제한을 넘지 못한다.
  - 본문은 공백을 정리한 뒤 5~300자다. 링크(주소 형태 포함)는 받지 않는다.
  - 계정마다 20초에 한 번, 하루 30개까지 쓸 수 있다.
  - 24시간 안에 같은 글은 다시 쓸 수 없다.
- **늦은 보상.** 글을 쓰고 10분(설정값)이 지나도 VISIBLE이면 그때 `PointIssuer`로 준다. 지운 글, 숨겨진 글, 하루 한도를 넘은 글은 주지 않는다(`NONE`).
  - 지급은 글 행을 잠그고 PENDING인지 확인한 뒤 한 트랜잭션에서 한다. 지급 기록의 멱등키 `post:글 id`가 마지막 방어선이다.
  - 하루 한도는 보상을 준 시각(KST) 기준으로 센다.
  - `PointIssuer.grantWithinLimit`은 한도를 넘으면 예외 대신 빈 값을 돌려준다. 바깥 트랜잭션에서 예외가 나면 그 트랜잭션 전체가 롤백 표시되기 때문이다.
- **신고와 숨김.**
  - 다른 계정 3명이 신고하면 자동으로 숨긴다. 같은 계정의 신고는 한 번만 세고(기본키), 자기 글은 신고할 수 없다.
  - 운영자는 숨기거나 되돌릴 수 있다(`/api/admin/posts`).

## 검토한 대안

- **쓰자마자 보상:** 도배 후 삭제로 하루 한도를 쉽게 채운다.
- **보상 회수:** 숨겨진 글의 보상을 빼앗으면 이미 쓴 포인트 때문에 잔고가 음수가 될 수 있다. 배당 정정과 같은 이유로 회수하지 않는다(0010).
- **운영자 승인 후 게시:** 대화가 끊긴다. 신고 누적 자동 숨김과 사후 검토로 충분하다.

## 결과

- 광고 시청 보상(AD_VIEW)은 광고 SDK 연동(M6) 때 같은 늦은 지급 구조를 쓴다.
- 금칙어 필터와 신고 누적 계정 제재는 운영 데이터를 본 뒤 정한다.
