# 0024. 경기 일정·결과는 API-Sports에서 받고, 배당 기준 시점을 늦추는 변경은 시작 전에만 받는다

- 상태: 채택
- 날짜: 2026-11-02

## 배경

승리 배당(ADR 0010)은 경기 결과로 지급한다. 지금까지는 운영자가 일정과 결과를 API로 넣었다. 매일 경기가 있는 KBO·K리그를 사람이 넣으면 늦거나 틀리고, 틀린 결과는 곧 틀린 배당이다. 무료로 쓸 수 있고 KBO와 K리그를 함께 주는 제공처가 필요했다.

## 결정

- **제공처.** API-Sports(API-Baseball v1 `games`, API-Football v3 `fixtures`). 같은 키로 둘 다 쓰고, 무료 요금제가 API별 하루 100회다. 응답을 제공처와 무관한 `FeedGame`(경기 번호, 팀 번호, 시작 시각, 상태, 점수)으로 옮긴 뒤 동기화하므로 제공처를 바꿔도 동기화 규칙은 그대로다.
- **해석.**
  - HTTP 200이어도 `errors`가 비어 있지 않으면 쓰지 않는다(키·요금제·한도 오류가 이렇게 온다).
  - 시작 시각은 `timestamp`(유닉스 초)로 읽는다. 날짜 문자열의 시간대 해석에 기대지 않는다.
  - 종료(FT, 축구는 AET·PEN 포함)라도 양 팀 점수가 다 있어야 결과로 본다. 모르는 상태 코드와 몰수·부전승은 UNKNOWN으로 두고 아무것도 하지 않는다. 제공처가 코드를 바꿔도 잘못된 결과로 배당하지 않는다.
- **팀 연결.** `teams.feed_source`, `feed_team_id`에 제공처 팀 번호를 운영자가 잇는다(고유 인덱스). 이름으로 맞추지 않는다. 연결이 없는 팀의 경기는 들이지 않고, 동기화 결과에 그 팀 번호와 이름을 돌려줘 운영자가 잇게 한다. 리그가 다른 구단끼리의 경기, 이미 받은 경기 번호의 팀이 바뀐 경우는 바꾸지 않고 기록만 남긴다.
- **일정 변경.** 배당은 예정 시작 시각에 가진 주식에만 준다(ADR 0010). 그래서 시각 변경을 방향에 따라 다르게 받는다.
  - 앞당기기: 언제나 받는다. 기준 시점이 이르게 될 뿐이라 결과를 보고 산 주식이 배당을 받는 일은 없다.
  - 늦추기: 제공처가 아직 시작 전(NS, 연기)이라고 할 때만 받는다. 경기 중에 시각만 늦게 고쳐 오면 경기를 보면서 산 주식까지 배당을 받게 되므로 받지 않고 기록만 남긴다.
- **새 경기.** 시작한 지 36시간이 안 된 경기만 들인다. 시즌 전체를 처음 받을 때 오래된 기록으로 지난 배당을 새로 만들지 않는다. 취소·모르는 상태의 새 경기도 들이지 않는다.
- **결과.** 종료 결과는 `recordResult`로 넣고, 지급은 기존대로 확정 대기(6시간) 뒤에 한다. 그 사이 점수 정정이 오면 대기를 다시 시작하고, 지급 뒤 정정은 REVIEW가 된다. 이미 끝난 경기를 제공처가 취소라고 하거나, 취소한 경기에 결과가 오면 바꾸지 않고 운영자에게 남긴다.
- **요청 수.** 6시간마다 리그별 시즌 전체를 한 번 받고(하루 4회), 15분마다 "시작하고 2시간 지났는데 결과가 없는" 경기의 날짜만 묻는다. 시작 6시간 뒤부터는 3시간에 한 번, 48시간이 지나면 더 묻지 않는다(운영자가 넣거나 취소한다). 보내기 전에 제공처별 하루(한국 시간) 90회 상한을 세고, 실패한 요청도 센다. 세는 값은 메모리에 있어 재시작하면 0부터 다시 세므로 상한을 100보다 낮게 둔다.

## 검토한 대안

- **KBO·K리그 공식 사이트 수집:** 공개 API가 없어 화면을 긁어야 한다. 화면이 바뀌면 조용히 틀린 값을 읽을 수 있고 이용 약관 문제도 있다.
- **결과가 바뀌면 그대로 따라가기:** 제공처의 실수가 곧바로 배당으로 이어진다. 확정 대기와 REVIEW로 사람이 볼 틈을 둔다.
- **시각 변경을 늘 받기:** 늦추는 변경으로 배당 기준 시점이 경기 중으로 옮겨 가면 결과를 보며 산 주식이 배당을 받는다.

## 남은 일

- 리그 번호(KBO 5, K리그1 292)와 무료 요금제에서 올해 시즌을 조회할 수 있는지는 키를 받은 뒤 `/leagues`로 확인한다.
- LCK는 API-Sports에 없다. 다른 제공처를 붙일 때 `FeedGame`으로 옮기는 해석기만 더한다.
